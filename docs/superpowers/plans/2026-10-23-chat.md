# N11 Chat: API and web moderation (2026-10-23, lane e)

Spec: build spec v4.1 section 3.10 ("Chat: direct and group messages in the app with moderation and reporting"),
build list #19, 3.15 (app: chat), launch acceptance "Chat works between two members of a club in the app".
This lane builds the API, the real-time hub and the admin moderation queue; the chat screens are in the app (later).

## What exists

- Nothing for chat. The goal-setting "district messages" are part of goal setting (being removed), not reused.
- Reused: JWT bearer auth (`memberId` claim), `ScopeWriteGuardMiddleware.AllowedAsync` (who manages a club or
  district), `AuditMiddleware` (logs every successful write under api/clubs|districts), `FeatureGate` (Kind.Flagged),
  `PersonalDataRegistry`, the admin `FeatureGate.tsx` link hiding, dashboard shells with `selectedClubId` /
  `selectedDistrictId`. SignalR is part of the ASP.NET Core shared framework: no new package.

## Build

Flag `chat` (Kind.Flagged, off until a SuperAdmin switches it on): API `^/api/chat(/|$)` (REST and the hub) and
`^/api/(clubs|districts)/\d+/chat-moderation(/|$)`; admin `/chat-moderation(/|$)`.

Tables (DatabaseInitializer + schema.sql, additive):
- `chat_conversations`: scope club|district, owner_id, kind direct|group, title (groups), direct_key (unique per club
  for a pair), created_by.
- `chat_members`: conversation, member, owner flag, last_read_message_id, muted_at/muted_by (moderator mute).
- `chat_messages`: conversation, sender, body (plain text, up to 2000 characters), client_key (idempotency),
  hidden_at/hidden_by (moderator hide).
- `chat_reports`: message, reporter, reason, resolved_at/by, resolution note.

Rules:
- Direct chats: two active members of the same club. Groups: club groups by any active member of the club; district
  groups (members of clubs in the district) started by the district's managers. Everyone in a chat must stay an
  active member of the club (or of a club in the district): a member who leaves the club loses the chat at once.
- Text is stored as typed and escaped when rendered (React text nodes in the admin, Text widgets in the app).
- Limits: 30 messages a minute per member, 20 reports an hour, 10 new groups an hour, 256 members a group (429/400).
- Moderators: the club's managers for club chats, the district's managers for district groups (same rule as
  ScopeWriteGuardMiddleware). They see reported messages only, never whole conversations.

Endpoints for the app (all `[Authorize]`, family sessions refused):
- `GET api/chat/conversations`
- `POST api/chat/conversations` `{ kind: "direct"|"group", scope: "club"|"district", ownerId, memberIds, title? }`
- `GET api/chat/conversations/{id}/members`
- `POST api/chat/conversations/{id}/members` `{ memberIds }` (group owner)
- `DELETE api/chat/conversations/{id}/members/{memberId}` (owner removes, or the member leaves)
- `GET api/chat/conversations/{id}/messages?before=&after=&limit=`
- `POST api/chat/conversations/{id}/messages` `{ body, clientKey? }`
- `POST api/chat/conversations/{id}/read` `{ messageId }`
- `POST api/chat/messages/{messageId}/report` `{ reason? }`
- Hub `/api/chat/hub` (SignalR, JSON protocol; token in `access_token` query): events `message`, `messageUpdated`,
  `read`. The hub has no client methods; the server pushes each event only to members who may read that chat.

Moderation (admin; `api/{clubs|districts}/{id}/chat-moderation`, managers only, every write in audit_log):
- `GET reports?status=open|resolved`
- `POST messages/{messageId}/hide`, `POST messages/{messageId}/unhide`
- `POST conversations/{conversationId}/mute/{memberId}`, `POST conversations/{conversationId}/unmute/{memberId}`
- `POST reports/{reportId}/resolve` `{ note? }` (closes every open report of that message)

Admin: `components/ChatModerationQueue.tsx`, pages `/club-admin-dashboard/chat-moderation` and
`/district-admin-dashboard/chat-moderation`, nav items in both dashboards (hidden while the flag is off).

e2e: `kb/tools/chat_e2e.py` (flag, direct and group chats, history, send, read state, idempotent retry, mute, hide,
report, resolve, rate limit, outsiders refused, hub delivery over long polling, WebSocket upgrade with the query token).

### For the app (later)

- Off switch: with `chat` off every chat route and the hub answer 404: hide chat. Family logins get 403: hide chat.
- Start: `POST api/chat/conversations` with `kind`, `scope`, `ownerId`, `memberIds` (member ids from the existing
  club directory screens), `title` for groups. Answers the conversation (same shape as the list); a direct chat that
  exists already comes back as is.
- List: `GET api/chat/conversations` (newest activity first): `id, scope, ownerId, kind, title` (group name or the
  other member's name), `otherMemberId, photo, memberCount, isOwner, muted, unread, lastMessageId, lastSenderId,
  lastBody, lastHidden, lastActivityAt`.
- Messages: `{ id, conversationId, senderId, senderName, body, hidden, createdAt }`, oldest first. `body` is plain
  text: render it as text. `hidden: true` with `body: null` means a moderator removed it.
- Send: `POST .../messages { body, clientKey }`; use a new random `clientKey` per message and resend the same one on
  a retry. 400 empty or over 2000 characters, 403 muted, 429 over 30 a minute.
- Read: `POST .../read { messageId }` after showing messages; members' `lastReadMessageId` gives seen marks.
- Real time: SignalR JSON hub at `{api}/api/chat/hub`, token through `accessTokenFactory` (sent as `access_token`).
  Events `message` and `messageUpdated` (a message; replace by id), `read` (`{ conversationId, memberId,
  messageId }`). An event for an unknown conversation means: reload the list. After a reconnect, call
  `GET .../messages?after=<last id>` for open chats.
- Report: `POST api/chat/messages/{id}/report { reason }` (204; 400 for your own message, 429 over 20 an hour).

### Open issues

- The hub token travels in the URL: reverse proxy or IIS access logs record query strings by default, and app tokens
  live 90 days. When hosting is decided, drop the query string from access logs for `/api/chat/hub`, or add a
  short-lived hub ticket.
- IIS needs its WebSocket Protocol feature for WebSockets; without it SignalR falls back to Server-Sent Events or long
  polling (works, slower).
- No push for new messages (no Firebase project yet) and no in-app feed entries (one per message would flood it):
  the app receives messages while connected and catches up when opened.
- Text only: attachments are out of scope. Mutes last until a moderator unmutes.
- A member who leaves the club loses the chats at once but keeps the rows; rejoining the club restores them.
- District groups need a starter who manages the district and is an active member of one of its clubs; on this copy
  no district Admin is a member of a club in their district, so the e2e grants a temporary role.
- Two identical sends racing with the same `clientKey` at the same instant: the second gets a 500 (duplicate key);
  a further retry returns the stored message.
- Admin pages were not rendered in a browser (next dev is not allowed in lanes); covered by tsc, check-design and the
  API e2e.
- Pre-existing, unrelated: `/swagger/v1/swagger.json` fails to generate on
  `GoalSettingController.ConvertFoundationClubFile` (`[FromForm]` with IFormFile).
